# Three Fable implementation loops

Objective: fix the audited delivery-kit controls, preserving the production floor and honest
evidence. This work does not rebuild RIOA or landscaping, generate images or prove the revised
workflow produces a satisfactory whole site. Fresh weekly usage baseline: 13%; user limit is
fewer than 5 additional percentage points. Planned effort: 2 implementation, 1 challenge/rework,
1 verification/Git completion, 1 buffer. These are allocations, not measured stage costs.

## Loop 1: implement the load-bearing controls

Verified foundations: the current prompt already has stages and fifteen fidelity gates;
historical runs left decisive comparisons open; the content source enum lacks original AI
imagery. The practical intervention is executable closure, not more production rows.

Implemented pinned sample/state/viewport coverage, hashed source and artifact inventories,
explicit dispositions, a typed generated source, private generation records, public lineage
entries, and pure content-sync preparation. Reference and adapted comparisons remain separate.
Existing 275 IDs/tiers and release_gate.py are preserved. Initial 79 kit checks and 82 tests passed.

Competing explanation retained: longer copy, approved branding and new media can change the
composition. The gate validates declared records; it cannot decide whether the criteria are
sufficient or measurements truthful. No causal or whole-site success claim follows from it.

## Loop 2: invert and repair false-completion paths

A narrow independent Luna Max review found five actual defects: undeclared generated content
could skip validation; client precedence conflicted with active registry equality; originals
could be public; deeply nested JSON produced traceback output; source URLs/captures were not
sufficiently bound. See [original review](INDEPENDENT_REVIEW.md).

Corrected all five. The adapted gate always inspects the app, even for an empty generated set.
Active generated slots must match exactly; client replacements retire public lineage entries
while private records can remain archived. Active originals cannot resolve inside public/.
Both CLIs return a normal incomplete result for recursive JSON. Absolute HTTP(S) source
metadata and source-file membership are bound to a hashed capture manifest.

Also checked the stronger stale-evidence case: a changed compiled file is rejected even when
its manifest was not rewritten. Named outputs report declared record completion and matching
model records, not independently verified visual truth or provider authenticity.

System effect: fewer opportunities to scale unchecked work, at the cost of explicit capture
and record maintenance. A false or incomplete inventory can still deceive a record validator;
coverage and factual review remain necessary. The intervention's net productivity is unmeasured.

## Loop 3: verify integration and both regression cases

Final local verification: 80 kit checks and 89 tests passed. Added 25 adversarial tests to the
existing 64. Empty/partial/idempotent sync, client replacement, malformed inputs, changed files,
duplicate/missing states, unknown model records, public originals and source binding are covered.
Final falsification also caught ignored misspelled result phases and possible source-enum drift;
strict phase validation and an enum mutation test now reject them.

A separate CLI rehearsal prepared content/manifest proposals and passed a complete synthetic
sample record with production_clearance false. Saved RIOA mobile 48px versus 37.44px and
landscaping 56px versus 92.3201px were then inserted as explicit failures; each independently
blocked expansion. An absent required GPT Image 2 record also blocked the claim. See
[rehearsal results](rehearsal.json). These are record-control probes using saved observations,
not new website renders, actual image generation or automated visual comparisons.

Stop/rollback: missing evidence produces an incomplete stage and resumable handover. Sync
preparation performs no app writes; the generated app must stage and verify its proposed pair
before committing, preserving the last good pair on failure. Changed dependencies require
fresh evidence. The existing production validator alone handles its separate release phases.

Verified: kit code, documented integration and adversarial behavior. Believed: enforcement and
scene-directed media will reduce the observed failure mechanisms. Unknown: complete-site
fidelity, generated-app sync integration, actual GPT Image 2 availability, repeatability and cost.
Next evidence is a bounded build rehearsal, not another static certainty claim.
