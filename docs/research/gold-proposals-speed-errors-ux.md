# Coordinator proposals: SPD, EDGE-01 to EDGE-04 plus new error-page rows, new UXF section, HOST-18

### KEEP SPD-01, SPD-02, SPD-03, SPD-04, SPD-05, SPD-07, SPD-08, SPD-09, SPD-10, EDGE-01

### REPLACE SPD-06
| SPD-06 | Hashed static files: `Cache-Control: max-age=31536000` (add `immutable`); HTML: `Cache-Control: no-cache` with `ETag`, so a repeat visit revalidates and gets a 304 with no body (web.dev/http-cache); `Vary: Accept-Encoding` on compressed responses. | `curl -sI` on every hashed asset in the build manifest (finding none is a `FAIL`) and on `/`; then `curl -s -o /dev/null -w '%{http_code}' -H 'If-None-Match: <etag>' <url>/` returns 304 | G |
**Why and sources:** adds the revalidation and Vary checks so a repeat visit costs one tiny round trip. web.dev/http-cache.

### REPLACE SPD-11
| SPD-11 | bfcache eligible, so back and forward are instant: no `unload` listener, no `Cache-Control: no-store` on the document, no open connections (IndexedDB, WebSocket, in-flight fetch) at navigation. Chrome, Firefox and Safari all support it (web.dev/bfcache). A blocker that comes from a library is fixed invisibly (for example an `unload` handler replaced by `pagehide`). | Lighthouse `bf-cache` audit, from the same performance run (Playwright-launched Chromium starts with `--disable-back-forward-cache`, so it cannot test this); grep the authored source for `unload` | G |
**Why and sources:** raised from R to G: 1 in 10 desktop and 1 in 5 mobile navigations are back or forward (web.dev/bfcache) and the fix is invisible.

### REPLACE SPD-12
| SPD-12 | Optional navigation speed-up by Speculation Rules, only as progressive enhancement (Chrome and Edge 109 and up, no Firefox, Safari behind a flag) and only when the site has more than one built route: `prefetch` or `prerender` with `moderate` eagerness (a 200 ms pointer hold or pointerdown) for same-origin internal routes, never `/api/`, downloads or any URL with side effects; the rules script carries a CSP hash (SEC-04); the page still works when unsupported; a prerendered page does not start the intro twice. | grep `speculationrules`; Playwright in Chromium: hover a link for 300 ms, then navigate, and `performance.getEntriesByType('navigation')[0].activationStart` is above 0; the page works with the rules removed | R |
**Why and sources:** developer.chrome.com/docs/web-platform/prerender-pages (eagerness levels, support, analytics caveat).

### NEW after SPD-12
| SPD-13 | Gold lab targets, median of 3 Lighthouse runs on the shipped build with `SITE_ENV=production`. Mobile profile (Slow 4G, 4x CPU): FCP ≤ 1.2 s, LCP ≤ 1.8 s, TBT ≤ 50 ms, CLS ≤ 0.02, Speed Index ≤ 2.0 s. Desktop profile (RTT 40 ms, 10 Mbps, no CPU slowdown): FCP ≤ 0.6 s, LCP ≤ 0.9 s, TBT ≤ 50 ms, CLS ≤ 0.02, Speed Index ≤ 1.0 s. Performance score at least 97 on both. INP proxy (SPD-01 method, mobile CPU slowdown) ≤ 100 ms. Each figure is the value at which the metric scores about 0.98 or better on Lighthouse's own curve (p10 and median values in its source, computed in the research notes), or the 0.1 s limit for feeling instantaneous (Nielsen); the choice of 0.98 is (J). Where the reference's own construction makes a target unreachable (a full-screen video or WebGL hero), rule 9 applies: record the measured value as a `FIDELITY-EXCEPTION`. The floors in SPD-01 are never waived. | Lighthouse JSON for both profiles ×3; the INP proxy run | G |
**Why and sources:** Lighthouse scoring source (GoogleChrome/lighthouse core/audits/metrics/*.js) and the Nielsen response-time limits.
| SPD-14 | The origin adds no delay. From `npm run start`, warm, 20 sequential requests each: time to first byte for `/` has p95 ≤ 50 ms and for one hashed asset p95 ≤ 20 ms (J: the origin must be negligible, the network adds the rest); the canonical URL answers with no redirect; the response is already compressed. | `curl -s -o /dev/null -w '%{time_starttransfer} %{num_redirects}'` in a loop with `Accept-Encoding: br`; p95 of the sorted times | G |
**Why and sources:** web.dev/ttfb counts redirects, DNS, TLS and request time in TTFB; the origin share is the part the build controls.
| SPD-15 | Edge response on the deployed URL: after one warm-up request, the median of 10 sequential `GET /` has time to first byte ≤ 200 ms and the p75 ≤ 300 ms from the auditor's location (J; web.dev's floor for good is 0.8 s), the HTML comes from the host's edge (cache status header where the host exposes one), and `http://` to the canonical `https://` URL costs at most one redirect. | `audit:live`: `curl -w '%{time_starttransfer} %{num_redirects}'` ×10 and the cache-status headers | G-L |
**Why and sources:** web.dev/ttfb; web.dev/optimize-lcp (about 40% of a good LCP is TTFB).
| SPD-16 | First flight: the compressed HTML document for `/` is at most 14 KB, so the first round trip can carry all of it (TCP's initial window is 10 segments of about 1,460 bytes, RFC 6928; QUIC's is similar). Critical CSS is inlined only while the document stays inside that size. Beyond it, record the size and the reason in the README. | `curl -s -H 'Accept-Encoding: br' -o /dev/null -w '%{size_download}'` on `/` | R |
**Why and sources:** RFC 6928 (initial window); the 14 KB figure is (J) as a budget.
| SPD-17 | Critical-path budget: the bytes needed before the LCP element paints (HTML, render-blocking CSS, the JavaScript and fonts that gate first render) total at most 170 KB compressed, initial JavaScript is at most 170 KB compressed, and neither exceeds the original's (web.dev performance-budgets-101 gives 170 KB as its mobile critical-path example; applying it here is (J)). Above the budget, record each library and its cost next to the original's figure; a library the original also loads and cannot be replaced invisibly is a `FIDELITY-EXCEPTION` (rule 9). | Playwright with CDP `Network.loadingFinished` `encodedDataLength` for every request that finishes before the LCP entry, summed by type; compare with `WS/baseline-original` | G |
**Why and sources:** web.dev/articles/performance-budgets-101.
| SPD-18 | No render blocking beyond one stylesheet: every `<script>` in the served HTML is `defer`, `async` or `type="module"` (or at the end of `<body>`); at most one render-blocking stylesheet, either inlined critical CSS or one file ≤ 30 KB compressed (J) that holds every first-render rule; no `@import` in any stylesheet; no font or image that is found only after CSS or JavaScript runs unless it is preloaded. | Playwright: parse the served HTML head; grep CSS for `@import`; Lighthouse `render-blocking-insight` and `network-dependency-tree-insight` (reporting audits) list nothing the row forbids | G |
**Why and sources:** web.dev/optimize-lcp (resource load delay and element render delay under 10% each); Lighthouse 13 insight audits render-blocking-insight and network-dependency-tree-insight exist (repository listing).
| SPD-19 | Text assets are precompressed at build (Brotli at its top quality and gzip at level 9) and served with the matching `Content-Encoding`, so the server never spends request time compressing; Brotli is preferred when offered. | Build output lists `.br` and `.gz` siblings; `curl -sI -H 'Accept-Encoding: br'` shows `content-encoding: br` | R |
**Why and sources:** (J) build practice; complements SPD-07.

### REPLACE EDGE-02
| EDGE-02 | The 404 page (real 404 status, SEO-03): the same header, navigation, footer, fonts, colours and background as the site; `<title>` "Page not found" with the site name; one `<h1>` in plain words ("Page not found"), and a visible "404" label is allowed; one or two plain sentences saying what happened and the usual causes (a mistyped address, an old link, a moved page), without blame or jargon; a primary action to the home page; 3 or more links to the main sections, generated from the built routes; the client's contact route (a `mailto:` or `tel:` link, the form, or a marked placeholder); no auto-redirect; no search box unless the site has search; `noindex`; works with JavaScript off; with JavaScript on, the `<h1>` takes focus on load (`tabindex="-1"`); no intro, loader, WebGL or video (EDGE-15). | curl the 404 status and head; Playwright with `javaScriptEnabled: false`: title, `<h1>`, link count and status of each link; axe on the page | G |
**Why and sources:** GOV.UK page-not-found pattern (plain H1, do not blame the user, avoid jargon, give contact details); Google Search Central crawling docs (real 4xx, soft 404).

### REPLACE EDGE-03
| EDGE-03 | 404 microcopy is specific, blame-free, jargon-free and never a dead end: it says what happened and the likely cause, then offers the next step (GOV.UK page-not-found pattern: do not blame the user, avoid technical jargon, avoid "oops" on formal brands). Examples: plain ("That page doesn't exist. The link may be old or mistyped. Head home or pick a section below."), warm ("Well, that went nowhere. Let's get you back on track."), minimal ("Page not found."). The voice follows the client's tone in `brief.md` when there is one, else plain. | Review | R |
**Why and sources:** GOV.UK design system, page-not-found pattern.

### REPLACE EDGE-04
| EDGE-04 | Missing asset URLs (images, scripts, fonts, `.map`) return 404, never `index.html` with 200, and an unknown `/api/*` path returns a JSON 404. Every 404 carries `Cache-Control: no-cache` or a `max-age` of 60 s or less, so a file or page published later is never hidden by a cached 404 (Cloudflare's default edge TTL for a 404 is 3 minutes). | `curl -sI <url>/img/none.png` and `<url>/api/none`; assert status and the `Cache-Control` header | G |
**Why and sources:** developers.cloudflare.com/cache/concepts/default-cache-behavior (404 TTL 3 m).

### NEW after EDGE-14
| EDGE-15 | The 404 page is light: no preloader or intro replay (unless the original's own 404 plays one, per the EDGE-01 baseline), no WebGL, video or heavy scripts, the compressed document is at most 14 KB, and on the mobile profile its LCP is ≤ 1.0 s (J). It is served at the requested URL, not through a redirect to a `/404` route. | Playwright and Lighthouse on `/no-such-page`: request list, transferred bytes, LCP; the final URL equals the requested URL | G |
**Why and sources:** someone who mistyped a URL should not wait through a loader; (J) figures.
| EDGE-16 | Progressive help on the 404 page (JavaScript only, nothing needed without it): it shows the requested path, inserted with `textContent` and never as HTML, and suggests the closest built route when one is within edit distance 2 (for example `/abuot` suggests `/about`), using the sitemap's paths. | Playwright: request `/abuot`; the page shows `/abuot` as text and links to `/about`; request `/<img src=x onerror=alert(1)>` and no script runs | R |
**Why and sources:** (J) usability practice; the safe-insertion check guards against reflected XSS.
| EDGE-17 | Known variants redirect instead of returning 404: `/index.html`, the other trailing-slash form, upper-case paths, `www` versus apex (SEO-07), and every URL that the original served at recon but the clone does not (from the EDGE-01 probe) answer 301 to the nearest built route or section, listed in the host redirect rules. | `curl -sI` on each variant shows 301 and the target | R |
**Why and sources:** Google Search Central (redirects versus 404); (J) practice.
| EDGE-18 | Server-error page: a static `500.html` (same header, fonts and background) is served with status 500 by `npm run start` when a request handler throws, and with 503 and `Retry-After` when the contact endpoint is unconfigured (BACK-01). It says something went wrong on the site's side, to try again shortly, and how to reach the client, and leaks no stack trace, file path or version. The nginx `error_page 500 502 503 504` equivalent is in `docs/DEPLOY.md`. | Start the server with `NODE_ENV=test`, whose only extra route `/__test/throw` throws: assert status 500, the page body, and no stack or path in it; the 503 case with no provider variables | G |
**Why and sources:** MDN HTTP 503 and Retry-After; OWASP error-handling guidance (group C covers the detail).

### NEW after HOST-17
| HOST-18 | Modern delivery on the deployed URL where the host supports it: HTTP/3 advertised (`alt-svc: h3=`), TLS 1.3 negotiated, Brotli served at the edge, and 103 Early Hints for the LCP image, the main stylesheet and the critical font when the host offers it (Cloudflare, Fastly and Akamai do; preconnect is supported in Chrome 103, Firefox 120 and Safari 17, preload in Chrome 103 and Firefox 123, not Safari). The host setting is named in `docs/DEPLOY.md` and verified by `audit:live`. | `curl -sI --http2 https://host` shows `alt-svc`; `curl -v --http2 https://host` shows a `103` response where enabled | R-L |

## NEW SECTION UXF: experience and conversion path
(after the EDGE section; ID prefix UXF)

### NEW UXF
| UXF-01 | No dead clicks: every control that looks or is marked interactive (an anchor, a button, `role=button` or `role=link`, anything with `cursor: pointer`) does something the visitor can see within 400 ms of activation (navigation, scroll, toggle, open, focus move or a state change), and no anchor has an empty, `#` or placeholder target. A control that does nothing in the reference is recorded as INHERITED in the baseline. | Playwright: enumerate interactive elements from the accessibility tree and the `cursor: pointer` set, activate each in a fresh context and assert a URL, scroll, focus or DOM change within 400 ms (MutationObserver), and run the same on the original | G |
**Why and sources:** Doherty threshold 400 ms (lawsofux.com).
| UXF-02 | Feedback is fast and honest: every pointer, touch or keyboard activation of a control paints a visible response (the reference's own hover, pressed, focus or state change) in the next frame and within 100 ms (the limit for feeling instantaneous, Nielsen). Where the site has a form, an action that waits on the network shows a pending state within 400 ms (Doherty) and a result or a timeout message within 10 s (Nielsen's attention limit), and the pending state does not shift layout. | Playwright at the mobile CPU profile: event timing `duration` for each control ≤ 100 ms; with a form, delay the endpoint 3 s (pending state by 400 ms) and 15 s (timeout message by 10 s) | G |
**Why and sources:** nngroup.com response-times-3-important-limits; lawsofux.com Doherty threshold.
| UXF-03 | Every call to action leads somewhere real and sits where the reference puts it: each CTA's destination is a built route, an existing `id`, a valid `mailto:` or `tel:` link or the working form, never `#`, `javascript:void(0)`, `example.com` or, on a `CLIENT-COMPLETE` build, a placeholder; and the primary CTA is in the first viewport at each of the four viewports wherever the reference's is (same rectangle within the rest tolerances). NN/g found 57% of viewing time above the fold in its 2018 study and advises keeping major CTAs there. | Playwright: for each slot with role `cta` resolve its href, request it, and compare its `x-rect-*` and first-viewport visibility with the baseline | G |
**Why and sources:** nngroup.com scrolling-and-attention.
| UXF-04 | Wherever a phone number or email address is shown it is a working link: `tel:` with the number in international format (for example `tel:+15550100`), `mailto:` with the client's real address and no prefilled subject or body containing visitor data; the visible text and link style are unchanged; the target meets RSP-05. | Playwright: regex on every `a[href^="tel:"]` and `a[href^="mailto:"]`; every phone-like or email-like string in the visible text sits inside such an anchor | C |
**Why and sources:** (J) practice; MDN URL schemes.
| UXF-05 | Form friction is minimal (forms only): never more fields than the reference has; required fields are marked in words as well as any symbol; each field has the right `type`, `autocomplete` token, `inputmode` and `enterkeyhint` (for example `inputmode="email"` with `enterkeyhint="next"`, and `enterkeyhint="send"` on the last field) so the phone shows the right keyboard; validation runs after a field is left, not while typing; an error sits next to its field, says how to fix it, is tied by `aria-describedby` and is never colour alone; the visitor's input survives any error; focus moves to the first error; success is announced in an `aria-live` region and does not wipe the page; a failed send (503 or timeout) keeps the text and offers the client's email address as a fallback. | Playwright at `mobile` and `desktop`: submit empty, invalid and valid data; assert attributes, messages, focus, preserved values and live-region text | C |
**Why and sources:** nngroup.com errors-forms-design-guidelines and error-message-guidelines; MDN enterkeyhint and inputmode (Baseline widely available).
| UXF-06 | Touch feels immediate: interactive controls set `touch-action: manipulation`, so a tap fires its click without the double-tap-zoom delay (MDN); show a pressed state on `:active` where the reference does; and have a hit area of at least 44×44 CSS px (WCAG 2.5.5, AAA; web.dev advises 48 px with 8 px spacing) built invisibly with padding or a pseudo-element. Where that would overlap a neighbour's hit area the row falls back to RSP-05 (24 px, no overlap) and lists the place. Hit areas do not change layout (rule 2). | Playwright touch context: computed `touch-action` on each control; the RSP-05 point-sampling grid over 44×44; the list of fallbacks | G |
**Why and sources:** MDN touch-action; W3C WCAG 2.5.5; web.dev accessible-tap-targets.
| UXF-07 | No deceptive design and no intrusive interstitials: nothing appears over the content without a visitor action, except the reference's own intro, a legally required consent banner (EDGE-12) and the 404 and error pages; no countdown, scarcity or social-proof claim that is not in `CLIENT_INPUT`; no pre-ticked consent or marketing box; no confirm-shaming wording ("No thanks, I don't like saving money"); no autoplay with sound (A11Y-14); no infinite scroll or feed unless the reference has one. Google treats full-page overlays that obscure content as intrusive, with exceptions for legally required consent and age gates. | Playwright: load and idle 30 s at each viewport; assert no `dialog`, `[role=dialog]` or fixed element covering more than 30% of the viewport appears without input; assert no `input[checked]` for consent or marketing; grep copy for countdown, scarcity and confirm-shaming patterns | G |
**Why and sources:** developers.google.com/search/docs/appearance/avoid-intrusive-interstitials.
| UXF-08 | Copy is real, selectable text, so find-in-page, translation, copy and read-aloud work: no heading or body text is drawn into an image, canvas or SVG path, and `user-select: none` is not set on body copy unless the reference does so for a gesture (recorded). | Playwright: every `text` slot's value appears in `document.body.textContent`; computed `user-select` on text slots; no `<img>` or `<canvas>` whose only purpose is text | R |
**Why and sources:** (J) practice; also supports SEO-04.
| UXF-09 | The five-second test: the first viewport says who the client is and what they do, in plain words. The `<h1>` or hero copy, the logo and the primary CTA together answer "whose site is this, what do they offer, what can I do next" without scrolling, at `desktop` and `mobile`. This checks the client's copy and slot mapping, not the reference's layout; a placeholder headline on a `CONTENT-PENDING` build is recorded as not yet answerable. | Review: screenshot the first viewport at both sizes and record the three answers in `WS/gates/visual-review.md` | R |
**Why and sources:** (J) usability practice.
| UXF-10 | The declared colour scheme matches the design, so the browser never re-colours it: `<meta name="color-scheme">` before any CSS and `color-scheme` on `:root` state the scheme the design really has (`light` only, `dark` only, or both when it has a toggle); form controls, scrollbars and the default canvas take matching colours; `only light` (or `only dark`) is used where the design must not be auto-darkened (MDN: `only` opts out of Chrome's Auto Dark Theme). The original's own scheme handling is kept (rule 2). | grep head; computed `color-scheme` on `:root`; Playwright `colorScheme: 'dark'` leaves a light-only design pixel-identical to its light frame | R |
**Why and sources:** developer.mozilla.org/en-US/docs/Web/CSS/color-scheme.
| UXF-11 | The path to the client's primary contact action is no longer than the reference's (for example open the menu, tap Contact, send), counted at `desktop` and `mobile` on both sites and recorded in the baseline and the README; a path longer than 3 interactions is listed in the README as inherited from the reference. | Playwright: shortest interaction path to the form, `mailto:` link or `tel:` link, counted on the original and the clone | G |
**Why and sources:** (J) conversion practice; the Deloitte and Google study of 37 brands found that a 0.1 s speed gain lifted lead-generation form progression by 21.6% (web.dev/case-studies/milliseconds-make-millions).
