# The production standard

Diamond is a release floor. Gold is a quality target above it. These are agency decisions, not certificates issued by a standards body. A small website and a payment application do not need the same features, but neither may mislead visitors or expose their data.

## Diamond: what must never be traded away

1. **People can read and use the site.** Text, controls and essential content work on small screens, with zoom, by keyboard and with supported assistive technology. Forms expose names, instructions, errors and status. Media and motion have the necessary alternatives and controls. Check real journeys as well as automated rules.
2. **The promised action works.** Navigation, enquiry, booking, account and payment flows that actually exist reach the intended result. A broken effect does not hide essential content. Pending, failed and uncertain actions tell the truth and offer recovery.
3. **Personal information stays protected.** Collect only what the service needs. Validate requests on the server. Protect private responses, sessions, uploads, records, secrets and logs. Apply authorization where data or privileged actions need it. A contact form does not require building an account system.
4. **The browser and server have appropriate defenses.** Use secure transport, suitable security policy, safe output handling and supported, reviewed dependencies. Address exploitable serious vulnerabilities. A particular library, deployment vendor or generic server name is not itself proof of danger.
5. **Privacy choices and notices match reality.** Inventory browser storage, hosting logs, providers and server-side sharing. Determine applicable rules. Obtain consent or honor opt-outs where required, and test the actual behavior. A cookie banner is not required merely to decorate a footer.
6. **Claims and rights are supportable.** No invented customers, results, reviews, prices or qualifications. Have rights to shipped content and required notices or attribution. Review reference-design risk where relevant. Resolve applicable legal duties with a competent reviewer, using counsel when necessary.
7. **The real destination works.** Verify the approved domain, certificate, deployed artifact and configured integrations. Test actual enquiry receipt when enquiries are promised. Protect existing business email during DNS changes. Provider acceptance alone does not prove inbox delivery.
8. **The release can be owned and recovered.** The authorized owner approves the actual release. Access, responsibilities and essential recovery steps are known. Back up data where it exists and prove the relevant recovery path. Keep private previews and unsafe reference builds private.
9. **The evidence tells the truth.** Checks identify the exact version, configuration, routes, states and test conditions. Unknown, failed, awaiting-owner and future checks stay visible. One evidence bundle can prove several controls; repeated paperwork does not create additional safety.

These are outcome summaries. The linked Diamond rows in [TIERS](TIERS.md) define the testable details. All applicable Diamond requirements must pass. A newly found serious defect or legal duty still blocks release if the catalogue omitted it. A scope change needs a real service decision, never a fabricated absence claim.

## Gold: what makes the site pleasant and dependable

- Pages load promptly, avoid disruptive layout movement and respond smoothly on representative devices and networks.
- Navigation, primary actions, forms and error recovery are clear. Touch controls are comfortable. Text and media remain stable while loading.
- Responsive layouts, translations, images and motion hold up across the supported audience's environments.
- Search and sharing metadata describe the real site. Redirects and links preserve useful destinations.
- Builds and handover instructions are reproducible and useful to the next operator.

Use measured outcomes and the actual acceptance scope. A generic Lighthouse score, one animation frame, a reference site's byte count or a prescribed folder name does not establish quality by itself. Field measurements need actual visitors; lack of sufficient traffic is missing evidence, not proof of a broken site. The catalogue states which later observations are enhancements.

## Silver and Bronze

Silver contains useful optimizations, diagnostics and optional operations. Bronze contains specialist/reference comparisons and legacy bookkeeping. Neither tier permits a weaker Diamond floor. A lower-tier item explicitly promised in the contract still blocks the delivery milestone when it is due until fulfilled or the scope is legitimately changed. Future support duties remain recorded with real due dates; they are not invented prelaunch evidence.

## The shortest honest workflow

1. Inventory the routes, critical actions, data, providers, audience and applicable duties. Mark conditional rows absent only when the absence is evidenced.
2. Build one reusable test bundle for each journey or risk. Map it to every row it actually covers. Keep the 275-ID register for traceability, without pretending it requires 275 separate test sessions.
3. Complete local Diamond checks, approvals and recovery preparation. Perform an authorized controlled cutover, then immediately verify final-domain checks. Roll back or disable the affected feature if a Diamond control fails.
4. Report Diamond, Gold and contracted scope separately. Record optional work with a reason and next action. Never call a historical failure a PASS because a later policy changed.

Reference imitation is its own commissioned deliverable. The cloning prompt's fidelity measurements remain relevant when that work is requested; they are not universal production safety rules.
