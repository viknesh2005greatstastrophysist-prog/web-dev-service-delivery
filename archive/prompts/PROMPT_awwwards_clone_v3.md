## Ground rules

These win over everything below and over the methodology repo.

1. **Unattended.** Do not stop between stages, do not ask for approval, do not ask questions. Run start to finish and report only when it's done or when a terminal state (§5) stops you.
2. **Computed styles are the ground truth.** Read them off the live page with `getComputedStyle`. Never read a value off a screenshot. Screenshots are a visual reference only, and the original-versus-clone gate is never a pixel diff. (Diffing your own clone against its own earlier frames, to prove a later change moved nothing, is allowed.)
3. **Your own browser automation.** Headless Playwright or Puppeteer, installed and driven by you, replaces the Claude Chrome extension everywhere the methodology repo mentions it.
4. **No lifted assets.** Do not hotlink from the original, do not ship its images, video, fonts or logo, and download none of them except images into `WS/evidence` as described below. Icons count as images: redraw or substitute them. Third-party brand icons come from an openly licensed icon set, with the licence recorded. Logos, wordmarks and client logos are replaced by a neutral mark of the same bounding box, weight and colour (for example the brand name set in the substitute font, or a geometric shape), never a traced or redrawn copy. Regenerate imagery in code, use freely-licensed equivalents (record each licence), or author placeholders that match the original's role, aspect, average luminance and dominant hue for that slot, so the paused frame reads the same and text over it keeps its contrast. Fonts are open-licensed faces (for example from Google Fonts or Fontsource), downloaded by you and self-hosted as `woff2` with their licence files, never loaded from a CDN at runtime. You may read the original's stylesheets, and fetch its images into `WS/evidence` only, to measure (colour, aspect, luminance) and for gate 6; alternatively save a screenshot crop of each image slot there. Never reference or ship evidence files. Write your own code from measured values: measured values are facts and stay identical, but do not ship the original's CSS, JS or markup. Gate 6 checks this at the end.
5. **Copy and links.** Keep the original's visible copy, so layout and line breaks match, except personal data (people's names in testimonials, emails, phone numbers, street addresses), which is replaced by placeholders of equal character length (`.example` domains, `555` numbers). Links to routes outside `SCOPE.md` point to the clone's own path and so reach the custom 404. External links to third parties keep their href. Links to the original's domain or subdomains become `#` with `aria-disabled="true"`. Add no visible text or link to any in-scope page for legal or production reasons: the unofficial-rebuild notice lives in the README, the 404 page, an HTML comment at the top of `index.html` and visually hidden text at the end of the footer (LEG-03). The sole exception is the demo form's post-submit message (BACK-01). Built pages name the original by brand name only, never by domain. The README states that this is an unofficial rebuild made for a comparison exercise and is not affiliated with the original's owner, and may give the original's URL.
6. **Honesty.** A gate is `PASS` only if its command output is saved under `WS/gates`. Never edit, delete, loosen or re-baseline an assertion to make it pass. Never call a frame pixel-identical while imagery or fonts are substituted; say what matches (layout, type metrics, colour, spacing, component states) and what is substituted. Report every gate that failed, was skipped or could not be measured. Verify everything yourself: re-run the gate, and never accept a delegated agent's report at face value.
7. **Servers.** Start dev and preview servers on fixed ports (`--strictPort`, `--host 127.0.0.1`), confirm the port is serving your build before trusting a capture (`curl -s <url>/build-id.txt` equals the random id that `npm run build`, or `npm run dev` at start, writes into the served output), and stop every server you started.
8. **Production grade, without costing fidelity.** Read the production checklist at `/Users/vik/Downloads/scrollcraft (2)/PRODUCTION_CHECKLIST.md` before stage 1, and copy it to `WS/PRODUCTION_CHECKLIST.md`. Its rules of application bind you: beat-or-match the original on every measured metric; a checklist row never changes anything a visitor can see or feel that the original shows, whether or not an assertion covers it (fix it invisibly first, otherwise keep the original's behaviour and log a `FIDELITY-EXCEPTION`); `G` rows must pass, `C` rows apply only if the feature exists, and every `N/A` needs a machine-checked absence predicate saved as evidence (checklist rule 7). The checklist has fifteen sections (SPD, TYP, RSP, A11Y, SEO, EDGE, MOT, SEC, BACK, MAIL, HOST, OPS, LEG, SUS, I18N) and all of them apply: `BACK` and `MAIL` rows are `N/A` for a static rebuild (record `BACK-00` as static); do not deploy to any public URL and do not create any hosting or other account: every live-only `-L` row is `N/A (not deployed)`, backed by the artifacts that make it pass on deploy and the exact command to run after; legal rows are engineering hygiene, not legal advice.

## 2. Recon every view before you write code

Every route in scope, at all four viewports. Every interactive state: hover, focus, active, open menus, modals, scroll-triggered states, loading and intro sequences, page transitions, drag and gesture states. Also record:

- **Rest frames.** For every section and state, the scroll position and timestamp where it is resolved: fully in view, reveals finished, the pointer never moved onto the page. "At rest" everywhere below means these frames.
- **Motion baseline** (`motion-baseline.json`). For the intro, menu open and close, page transitions and scroll reveals: computed `transform` and `opacity` every animation frame, recorded in-page with a `requestAnimationFrame` recorder timestamped by `performance.now()` from the triggering event, plus frames. For scroll-driven motion (parallax, pins, scrubs): the computed values at a fixed list of scroll offsets.
- **Canvas and WebGL surfaces.** Rect, what drives each one (time, scroll or pointer), how it behaves over time, and whether the surface is DOM or GPU-rendered.
- **Runtime-only behaviour.** Injected style tags, custom cursors that only appear after the first pointer move, consent banners (handle them the same way on both sites when capturing).
- `interaction-map.json` (contract §8) with an honest `unreached[]`, and `STATES-MANIFEST.md`.
- **Never send a state-changing request to the original.** Do not submit a form, subscribe, sign up, add to cart or send any other write to the live site. Dismissing a consent banner with its Reject or essential-only choice is allowed, and is done identically on both sites. Record those post-submit states in `unreached[]` with the reason `state-changing on a live site` (allowed without a trigger attempt), take their styling from the authored rules in the original's stylesheets, and exclude them from target validation.
- **Baseline audit of the original** (`WS/baseline-original`): Lighthouse mobile and desktop (3 runs each, median), axe results per state, response headers (`curl -sI`), transferred bytes and request count, console errors, `robots.txt`, favicon and manifest presence, hosting fingerprint (TLS protocol, HTTP version, CDN and cache headers, IPv6), cookies set and third-party origins requested, consent-banner behaviour, legal links present (privacy, terms, accessibility statement, imprint), language alternates, and its 404 behaviour (a random missing path, a missing asset, a bad query), with a screenshot of its 404 page. This is the bar the clone must meet or beat (checklist rule 1 and EDGE-01). Cache every measurement of the original in `WS/evidence` and reuse it. Use at most one page load per 10 seconds against the original, and a descriptive User-Agent. If `robots.txt` disallows a scoped route for all user agents, choose another target. A 403 or 429 is a `HARD-BLOCKER` after one retry 10 minutes later.

Award sites are slow headless: use `waitUntil: 'load'`, 90 s timeouts, retries and 10 to 13 s settles. What you miss in recon you will not build.

## 3. Extract, specify, assert

Pull real computed values off the live page: computed-style archetypes per page × viewport, pseudo-elements, CSS variables, `@font-face` rules, the authored stylesheet rules (media queries, keyframes, easings), the full type scale, the colour palette with exact values, spacing, radii, shadows, borders, grid and container widths, measured breakpoints, and a fingerprint of the stack and scroll library. Measure motion numerically: durations, easings, staggers, distances, lerp and inertia constants, parallax factors, clamp bounds, the scroll library's settings. Never read a value off a screenshot.

Then write `DESIGN.md` (contract §4) and `assertions.json`: an array of `{selector, prop, expected, layer}`, one entry per viewport × state × selector × property.

- `selector` is `"<viewport>|<state>|<css selector>"`. `prop` is a kebab-case CSS longhand (`padding-left`, never `padding`) or one of the pseudo-properties below.
- `layer: "rest"`: colour, background (gradients included), type metrics, padding, margin, radius, box-shadow, backdrop-filter, position, z-index, cursor, rects (`x-rect-*`), and the final `transform` and `opacity` of each state.
- `layer: "motion"`: `transition-*`, `animation-*`, `scroll-behavior`.
- `layer: "substituted"`: only `font-family`, `src` and `background-image` values that contain `url(`, and `x-rect-width` of elements whose width is set by their own text in a substituted font. The strict comparator fails any other prop labelled `substituted` and prints the substituted count per viewport, which the README reports. List every substituted value, with the original and clone values, in `WS/substitutions.json`.
- Pseudo-properties (layer `rest`, never `substituted`; the only non-CSS props allowed): `x-line-count` (number of distinct line boxes from `Range.getClientRects()` over the block's text), `x-line-starts` (the first word of each line joined by `/`, compared exactly, which is what makes "line breaks land in the same places" checkable), and `x-rect-top`, `x-rect-left`, `x-rect-width`, `x-rect-height` in px.
- Coverage: your assertion builder prints `archetypes covered: X/Y` and `states covered: X/Y`. Both must be 100%.
- **Lock.** `WS/assertion-changes.md` starts with the initial SHA-256 of `assertions.json`. Every change appends the reason, the measurement file it came from and the new SHA-256, and rewrites `WS/gates/assertions.lock`. Regenerate assertions only from a new measurement of the original. Each change is its own git commit.

## 4. Rebuild it

Every page in scope, every component, every state, at every breakpoint, in a modern framework of your choice. The motion is part of the clone: rebuild the original's own scroll behaviour, page transitions, hover choreography, entrance animations and any WebGL or canvas work first, and only then anything else. For WebGL and canvas, author the effect yourself from what recon recorded. A static skin over a site whose whole identity is motion is a failed clone.

- **Fonts.** Choose the closest open font by measuring about 30 candidates against the live font (cap-height-normalised text width, x-height, uppercase width). Use `size-adjust` in `@font-face` where it improves the match. Record the numbers.
- **Imagery.** Write the shot list right after recon and build placeholders at every slot's aspect, so QA can run before the final images exist. Never upscale beyond a source's resolution, and never bake text into an image. Look at every generated image before using it.
- **Build discipline.** Never define components inside other components. Guard effects that run twice under React StrictMode in dev, and test `npm run dev` as well as the production build. A `position: fixed` element at `left: 50%` is capped at half the viewport: give a large centred title `width: max-content`. Write colour alpha as a decimal (`rgb(0 0 0 / 0.5)`), because a percentage can read back as 0.498.
- **Production build.** Ship everything the checklist's `G` rows need, not just the page: landmarks, heading semantics and alt text added without changing computed styles; a complete icon set and manifest; metadata and `noindex` (SEO); a custom 404 page and an app-level error boundary (EDGE); a no-JS baseline and a no-WebGL fallback; self-hosted fonts and libraries (SEC-05, LEG-01); reduced-motion behaviour (A11Y-09); and a production server behind `npm run start` that serves `dist` with compression, cache headers, security headers and a real 404 (SEC-01); `npm run build` and `npm run dev` each write a random `build-id.txt` to the served root (used by ground rule 7). Also ship the deploy-ready artifacts (checklist rule 5): the host's header file, a root `404.html`, `docs/DEPLOY.md` (architecture, runbook, exact verify commands) and a CI workflow (build, typecheck, lint, tests, audit, Lighthouse budgets, and an `npm run verify` that runs them; OPS-01, OPS-02). Add the legal and content hygiene the rows require: a privacy notice or a one-line no-data statement (LEG-11); `THIRD_PARTY_NOTICES` and a licence table for fonts, images and libraries (LEG-14); the unofficial-rebuild notice (LEG-03); no cookies by default, a consent banner only if a non-essential cookie exists, and Global Privacy Control honored (LEG-09, LEG-10); `hreflang` and `lang` handling if the original is multilingual (I18N-01); `Save-Data` handling and pausing of hidden-tab work (SUS-02). Every form the original has keeps its original look and follows BACK-01: it POSTs to a same-origin `/api/demo-form` served by `npm run start`, which validates and returns 202 without storing or sending anything, and the form then shows the original's own success component with the text "Demo rebuild: nothing was sent." That endpoint is server code, so BACK-02, BACK-03, BACK-04 and BACK-07 apply and `MAIL` stays `N/A`. Any other server code makes every `BACK` row apply.

## 5. Prove the match

**The comparator.** The contract names `assert-styles.mjs` as the gate, and you run it, but on its own it can pass a false match: it compares only the first number in any value that has units. Reproduced: a `padding` of `10px 60px` passes against an expected `10px 20px`, and a `box-shadow` with a different colour, offset and blur passes when its first number matches. Also reproduced: `opacity` 0 against 1, `transition-duration` 0.3s against 1.2s, `z-index` 10 against 11 and a line count of 3 against 4 all pass. So write `WS/tools/assert-strict.mjs`, which reads the same two JSON files plus each assertion's `layer` and compares token by token.

- Tolerances: `px` ±1, `em` and `rem` ±0.01, `%` ±0.5, `s` ±0.005, `ms` ±5, `deg` ±0.5, opacity and colour alpha ±0.01; in `matrix()` and `matrix3d()` the translation entries ±1 px and every other entry ±0.001. Colour channels, unitless numbers (`font-weight`, `z-index`), keywords and function names must match exactly, and a value with a different number of tokens fails. A selector or property missing from the clone's styles is a failure, never a skip. `substituted` entries are skipped and counted, subject to the allowlist in §3.
- Exit 0 only when `rest` and `motion` have zero failures.
- Smoke test before you use it, saved to `WS/gates/strict-smoke.txt`, with exactly these six cases: `transform-origin` `10px 20px` against `10px 60px` (must fail); `box-shadow` `rgba(0, 0, 0, 0.5) 0px 4px 12px 0px` against `rgba(0, 255, 255, 1) 0px 40px 90px 30px` (must fail); `opacity` `1` against `0` (must fail); `transition-duration` `0.3s` against `1.2s` (must fail); `width` `400px` against `400.9px` (must pass); a selector missing from the clone's styles (must fail). The upstream script passes the first four.

Run both comparators and save both outputs. The strict one is the gate.

**Clone gate.** Drive each state exactly as a user would (move the pointer, hover, click, scroll in steps, wait for transitions to end), read `getComputedStyle` for every asserted key into `clone-styles.json`, and run the comparators. Iterate the convergence loop until there are zero `rest` and `motion` failures and `npm run build` exits 0.

**Target validation (required).** Assertions are keyed by original selectors, and `WS/selector-map.json` maps each to a clone selector. Run the same reader against the live original, and against the clone through the map, scored with the same assertions. Every mismatch means the spec recorded an authored value where the runtime computes something else (for example a JS-injected `cursor: none`, or an unscoped variable falling back to black). Correct the assertion to the runtime value (log it in `assertion-changes.md`), fix the clone to match, and re-run both. Final state: the clone has 0 failures and the original has 0 failures on the same `rest` and `motion` set (excluding states marked `state-changing on a live site`). Record the URL, capture date, viewport, font-load state and interaction state with both runs. If the live site changes during your build, refresh the baseline and say so.

**Motion gate.** Record every recorded motion sequence on both sites with the same in-page `requestAnimationFrame` recorder, started by the same dispatched trigger event. End values must be within the rest tolerances. Completion time, the first frame after which the value stays within tolerance of its end value, must be within ±50 ms. At each 16 ms step, `abs(clone - original) / max(abs(range), 1 unit)` must be at most 0.08, where range is end minus start of the original; a property with zero range is compared with the rest tolerances. For scroll-driven motion, computed values at the same scroll offsets must meet the rest tolerances. Anything you cannot measure numerically (shader output, for example) goes in a list of unmeasured items with a frame-strip comparison instead.

**Production gate.** Write `WS/tools/prod-audit.mjs`. It runs every checklist row whose Verify column names a command or snippet, against `npm run start`, at the four viewports (and in Chromium, WebKit and Firefox where a row says so), and writes `WS/gates/production.json` (row ID, status, measured value, evidence path) plus a readable `WS/gates/production.md`. It also runs the `BACK` rows against the local server when server code exists, and records every `-L` row as `N/A (not deployed)` with the exact command to run after deploy (never deploy publicly). Smoke test before use, saved to `WS/gates/prod-smoke.txt`: on a deliberately broken fixture (a server that answers 200 for a missing path, a page with no `lang`, an image without `width` and `height`) it must fail SEO-03, TYP-05 and SPD-04. Rows that need judgment (microcopy, composition) are filled in by hand in the same table. Run the same audit on the original for the baseline (§2) and print clone versus original for every numeric row. Record each `FIDELITY-EXCEPTION` in `WS/fidelity-exceptions.md` (row, the original's value, the cost of fixing it, what you did instead).

**Convergence loop** (contract §6). At most 10 cycles. Two consecutive cycles with no drop in failures, from cycle 2, end the run as `STUCK`. Reaching the cap is `CEILING`. A blocked target or a build that won't compile is `HARD-BLOCKER`. On any of these, write `WS/escalation.md` and say plainly what failed. Never present it as passing. Failure counts in the loop are the strict comparator's `rest` plus `motion` failures.

**Eyeball pass** (after the gate is green). Side-by-sides, original next to clone, at the recorded rest frames at all four viewports and every key state, plus frame strips of the intro, transitions and scroll reveals. Fix what the assertions cannot see: clipping, stacking, remounts, timing, line breaks. A long capture batch can catch a crossfade mid-transition, so re-shoot before you "fix". Save the clone's rest frames as PNGs in `WS/09-polish/rest` (reveals finished, `document.fonts.ready` resolved, the pointer never moved onto the page) as your visual record. §6 takes its own baseline after `07-polish.md`, because that stage edits page code.
