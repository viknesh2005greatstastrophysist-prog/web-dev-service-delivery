## Inputs

Client materials are optional at run time. Never stop because they are missing. Look for `CLIENT_INPUT` (default `./CLIENT_INPUT`; the run message may give another path). Everything the client supplied is used, and every slot it did not supply is filled in **template mode** and flagged, so every run ends with a complete, working site. A file that is missing, empty, unreadable, corrupt or in an unsupported format counts as not supplied. Expected files, all optional:
- `brief.md`: the business, audience, tone, niche, languages, the client's domain (`SITE_URL`), competitors to avoid as design targets, and optionally a target the client likes (`TARGET_URL`).
- `copy.md` or `copy.json`: every text the site needs, keyed by section: navigation labels, headings, body, calls to action, footer, testimonials, contact details, social links, form labels and success and error messages, and the legal entity name.
- `images/` with `images.csv` (file, optional slot key, alt text or `decorative`, focal point, credit and licence), and `logo/` (the client's own logo files: SVG, PNG or WebP).
- `fonts/`: licensed web font files of the original's typefaces, with their licence, if the client owns one. A different brand font is listed in `docs/CONTENT_NOTES.md` and not used, because the type stays the reference's.
- `rights.md`: the client attests that it owns or licenses every copy, image, logo and font supplied, and lists releases for identifiable people.
- `legal.md`: jurisdiction, legal entity, whether forms, email, accounts, payments, analytics or cookies are used, who receives form submissions, which email provider sends them, and how long enquiries are kept.

**Template mode** (per slot, never the original's words, images or brand):
- Copy: neutral filler with the original slot's role and exact word lengths, so line breaks land where the original's do. `WS/tools/filler.mjs` makes it deterministically from `WS/slots.json`: for each word of the slot, in order, it takes the next word of the same length from the standard Lorem ipsum passage (`Lorem ipsum dolor sit amet` to `id est laborum`), cycling through each length's words in document order across slots (a longer word joins lexicon words without a space), keeping the slot's spaces, punctuation and capitalisation pattern and turning digits into letters. For headings, calls to action and navigation labels, the first k words are the first k words of a role phrase (`Your headline here`, `Call to action`, `Page`), where k is the largest number for which those words are no longer, in characters, than the slot's first k words. Filler contains no digits, prices, names, awards, claims or quotations. Contact details are `hello@example.com`, `+1 555 0100` and `123 Example Street`, social links point to `https://example.com/`, and the legal entity is `Your Company Ltd`.
- Images: neutral placeholders generated in code as raster files at the slot's aspect and sizes, in the same `<img>` or `<picture>` markup a client image will use, with `alt=""`, in a tone matching the original slot's average luminance and hue family (a diagonal gradient or flat colour with subtle grain, no text).
- Logo: a wordmark of the client's brand name from `brief.md` or the copy, else `Your Brand`, set in the site's heading font. Any logo, the client's or this wordmark, is scaled without distortion to fit inside the original logo slot's bounding box and aligned as the original's logo is.
- Everything else: assume the minimum. Open-licensed fonts; no accounts, payments, analytics or cookies; a contact form only where the original has one, with no email provider configured (it answers 503, BACK-01); the language is `en`; no brief means you choose the target yourself (§1) and `WS/NICHE-RULES.md` holds only the generic claim rules (CNT-05); `SITE_URL` is `https://example.com`.

**Mapping** (deterministic; every decision is listed in `docs/CONTENT_NOTES.md`). Copy keyed by slot key, in the format of `docs/client-input-template/copy.json` (§7), maps directly; free-form copy maps by role (heading, body, call to action, label) in document order within the matching section. An image goes to the slot named in `images.csv`, else to the slot whose key matches its filename, else in filename order to the remaining image slots in document order; the focal point defaults to the centre. Never add, remove or repeat a section, list item or form to fit the content: surplus content is listed as unused, and missing content uses template mode. An image with no alt text gets a short literal description (no names, brands, places or claims) marked `placeholder: true` for the client to confirm; one marked `decorative` gets `alt=""`. A client SVG is sanitised (scripts, event handlers and external references removed). With several languages, the first in `brief.md` is the default and each other one is served under `/<lang>/` from the same templates; a missing translation shows the default language's text with `lang` set on its element, marked as a placeholder, never machine-translated. The fidelity gates run on the default language; the copy-fit gate and the content probe run on every language. Client pages that no route in `SCOPE.md` carries are listed, not built.

All copy and image references render from one content file, `content/site.json` in the app, so replacing content never touches code. Each slot has its key (from `WS/slots.json`), a kind (`text`, `image`, `link` or `logo`), its value (plus `alt` and `focal` for images), a `source` and `placeholder`. `source` is `client`, `template`, or `system`: interface, form, error and legal-draft copy that you write plainly in the site's language where the client supplied none (skip link, menu and close labels, form labels and messages, the 404 text, `<noscript>` text, consent-banner text, the legal drafts). System copy makes no claim about the client, and its only numbers are the 404 status, the current year, and counters, indices or percentages the design itself generates. `placeholder` is true exactly when `source` is `template`. Every placeholder is machine-marked: `data-placeholder="<slot>"` on its element, and `placeholder` in its image filename (fixed-name icon files are marked in `content/image-manifest.json` instead). Write `WS/tools/validate-input.mjs` to report what was found and which slots fell back to template mode; it never fails the run. The content status is `CLIENT-COMPLETE` when no slot is a placeholder and `rights.md` (naming or covering every supplied file) and `legal.md` were supplied; otherwise it is `CONTENT-PENDING` with the counts of placeholder slots and missing files, which is a normal finished state and not a blocker.

## Ground rules

These win over everything below and over the methodology repo.

1. **Unattended and never blocked.** Do not stop between stages, do not ask for approval, do not ask questions. Run start to finish and report only when it's done. Nothing ends the run early: missing client materials use template mode (Inputs), a gate that fails is reported as `FAIL`, a tool or file you cannot get makes only the gates that need it `NOT_RUN`, and a convergence-loop terminal state ends only the loop (§5). Every run ends with the handover package (§7) and the final message (Finish).
2. **Computed styles are the ground truth.** Read them off the live page with `getComputedStyle`. Never read a value off a screenshot. Screenshots are a visual reference only, and the original-versus-clone gate is never a pixel diff. (Diffing your own clone against its own earlier frames, to prove a later change moved nothing, is allowed.)
3. **Your own browser automation.** Headless Playwright or Puppeteer, installed and driven by you, replaces the Claude Chrome extension everywhere the methodology repo mentions it.
4. **No lifted assets.** Do not hotlink from the original, do not ship its images, video, fonts, logo, icon artwork or text, and download none of them except its images, stylesheets and visible text into `WS/evidence`, as described below. Imagery is the client's (`CLIENT_INPUT/images`), processed for the site: cropped to each slot's aspect around the focal point, AVIF or WebP with fallbacks, never upscaled. A slot the client did not fill gets a machine-marked neutral placeholder (Inputs) and an entry in `docs/CONTENT_GAPS.md`, never the original's picture. The logo is the client's own (or the template wordmark), fitted inside the original's logo slot (Inputs), never a traced or redrawn copy of the original's. Icons: draw your own or use an openly licensed icon set (record the licence); third-party brand icons (social networks) also come from an openly licensed icon set. Fonts: the original's commercial fonts may not be downloaded or shipped. Use the client's licensed files from `CLIENT_INPUT/fonts` if supplied, otherwise the closest open-licensed face (for example from Google Fonts or Fontsource), measured against the live font, downloaded by you and self-hosted as `woff2` with its licence file, never loaded from a CDN at runtime. You may save the original's stylesheets, visible text and images into `WS/evidence` only, to measure (aspect, luminance, slot geometry, word lengths) and for gates 6 and 13; instead of its images you may save a screenshot crop of each image slot there. Never reference or ship evidence files. Write your own code from measured values: measured values are facts and stay identical (the original's colours, spacing, type scale and easings are the design reference), but do not ship the original's CSS, JS or markup. Gate 6 checks this at the end.
5. **Client content and links.** Every visible word, image, logo, name, testimonial, number, contact detail and legal identity comes from `CLIENT_INPUT` or, for a slot the client did not supply, from template mode or system copy (Inputs). None of the original's text or brand assets ships; interface words that happen to match the original's (for example "Menu", "Close", "Next") are system copy. Never edit, shorten, rewrite or improve the client's copy; if it does not fit a slot, keep it and let the copy-fit gate record it (§5). Never invent facts: prices, statistics, awards, credentials, testimonials, client names, guarantees and outcome claims appear only if they are in `CLIENT_INPUT`, and template filler contains none of them. Empty slots are filled in template mode and flagged in `docs/CONTENT_GAPS.md`; the content status is then `CONTENT-PENDING`, which is a normal finished state and never a reason to stop. Internal links go to a built route or an in-page section: a navigation item whose page is not built links to the matching section of a built route, else `/`, and is listed in `docs/CONTENT_NOTES.md`, so no internal link returns 404 (SEO-08). External links use the client's URLs; nothing links to the original or its domain. The original's name and URL appear only in `docs/PROVENANCE.md` and the README, which are not served. Public pages carry no notice about the original.
6. **Honesty.** A gate is `PASS` only if its command output is saved under `WS/gates`. Never edit, delete, loosen or re-baseline an assertion to make it pass; an entry moves to `content` only through the content probe (§3). Never call the site pixel-identical: the content is the client's by design and fonts may be substituted; say what matches (design system, layout, type metrics, colour, spacing, component states, motion) and what is the client's. Report every gate that failed, was skipped or could not be measured. Verify everything yourself: re-run the gate, and never accept a delegated agent's report at face value.
7. **Servers.** Start dev and preview servers on fixed ports (`--strictPort`, `--host 127.0.0.1`), confirm the port is serving your build before trusting a capture (`curl -s <url>/build-id.txt` equals the random id that `npm run build`, or `npm run dev` at start, writes into the served output), and stop every server you started.
8. **Production grade, without costing design fidelity.** Read the production checklist at `/Users/vik/Downloads/scrollcraft (2)/PRODUCTION_CHECKLIST_client.md` before stage 1, and copy it to `WS/PRODUCTION_CHECKLIST.md`. Its rules of application bind you: beat-or-match the original on every measured metric; a checklist row never changes the original's design system, layout, motion or behaviour that a visitor can see or feel, whether or not an assertion covers it (fix it invisibly first, otherwise keep the original's behaviour and log a `FIDELITY-EXCEPTION`, which you also list for the client in `docs/FIDELITY_EXCEPTIONS.md` because it can be an accessibility-law risk, and you ship its fix switched off by default behind the `A11Y_FIXES` build flag, §4); `G` rows must pass, `C` rows apply only if the feature exists, and every `N/A` needs a machine-checked absence predicate saved as evidence (checklist rule 7). The checklist has seventeen sections (SPD, TYP, RSP, A11Y, SEO, EDGE, MOT, SEC, BACK, MAIL, HOST, OPS, LEG, SUS, I18N, CNT, DEL) and all of them apply. You do not deploy, create any hosting, email or other account, or handle credentials: a human deploys the finished package and then runs `npm run audit:live -- <site url>`, which checks every live-only `-L` row. Until then those rows are `AWAITING-DEPLOY`. Owner-only `-O` rows (accounts, monitoring, backups, timed drills) are `OWNER-CONFIRM`, each listed in `docs/LAUNCH_CHECKLIST.md` with its confirmation step. ## 2. Recon every view before you write code

Every route in scope, at all four viewports. Every interactive state: hover, focus, active, open menus, modals, scroll-triggered states, loading and intro sequences, page transitions, drag and gesture states. Also record:

- **Rest frames.** For every section and state, the scroll position and timestamp where it is resolved: fully in view, reveals finished, the pointer never moved onto the page. "At rest" everywhere below means these frames.
- **Motion baseline** (`motion-baseline.json`). For the intro, menu open and close, page transitions and scroll reveals: computed `transform` and `opacity` every animation frame, recorded in-page with a `requestAnimationFrame` recorder timestamped by `performance.now()` from the triggering event, plus frames. For scroll-driven motion (parallax, pins, scrubs): the computed values at a fixed list of section-progress values (0 when the section's top meets the viewport's bottom, 1 when its bottom meets the viewport's top; for a pinned section, the pin's start and end), because the client's content changes section heights and pixel offsets. Record for each effect whether it is progress-based (a tween over the section) or a per-pixel factor (parallax speed, scroll lerp).
- **Canvas and WebGL surfaces.** Rect, what drives each one (time, scroll or pointer), how it behaves over time, and whether the surface is DOM or GPU-rendered.
- **Slot map** (`WS/slots.json`): for every text slot and image slot in scope, its role, the original's character count, word lengths and line count per viewport, aspect ratio, focal region, average luminance, hue family, and whether text sits over it. The client's content is fitted against this in §5.
- **Runtime-only behaviour.** Injected style tags, custom cursors that only appear after the first pointer move, consent banners (handle them the same way on both sites when capturing).
- `interaction-map.json` (contract §8) with an honest `unreached[]`, and `STATES-MANIFEST.md`.
- **Never send a state-changing request to the original.** Do not submit a form, subscribe, sign up, add to cart or send any other write to the live site. Dismissing a consent banner with its Reject or essential-only choice is allowed, and is done identically on both sites. Record those post-submit states in `unreached[]` with the reason `state-changing on a live site` (allowed without a trigger attempt), take their styling from the authored rules in the original's stylesheets, and exclude them from target validation.
- **Baseline audit of the original** (`WS/baseline-original`): Lighthouse mobile and desktop (3 runs each, median), axe results per state, response headers (`curl -sI`), transferred bytes and request count, console errors, `robots.txt`, favicon and manifest presence, hosting fingerprint (TLS protocol, HTTP version, CDN and cache headers, IPv6), cookies set and third-party origins requested, consent-banner behaviour, legal links present (privacy, terms, accessibility statement, imprint), language alternates, and its 404 behaviour (a random missing path, a missing asset, a bad query), with a screenshot of its 404 page. This is the bar the clone must meet or beat (checklist rule 1 and EDGE-01). Cache every measurement of the original in `WS/evidence` and reuse it. Use at most one page load per 10 seconds against the original, and a descriptive User-Agent. If `robots.txt` disallows a scoped route for all user agents, choose another target. A 403 or 429 during target choice or recon, after one retry 10 minutes later, means you pick another target and record the swap (§1); after recon, keep the target, use the cached evidence, and mark the gates that need a live read `NOT_RUN`.

Award sites are slow headless: use `waitUntil: 'load'`, 90 s timeouts, retries and 10 to 13 s settles. What you miss in recon you will not build.

## 3. Extract, specify, assert

Pull real computed values off the live page: computed-style archetypes per page × viewport, pseudo-elements, CSS variables, `@font-face` rules, the authored stylesheet rules (media queries, keyframes, easings), the full type scale, the colour palette with exact values, spacing, radii, shadows, borders, grid and container widths, measured breakpoints, and a fingerprint of the stack and scroll library. Measure motion numerically: durations, easings, staggers, distances, lerp and inertia constants, parallax factors, clamp bounds, the scroll library's settings. Never read a value off a screenshot.

Then write `DESIGN.md` (contract §4) and `assertions.json`: an array of `{selector, prop, expected, layer}`, one entry per viewport × state × selector × property.

- `selector` is `"<viewport>|<state>|<css selector>"`. `prop` is a kebab-case CSS longhand (`padding-left`, never `padding`) or one of the pseudo-properties below.
- `layer: "rest"`: colour, background (gradients included; image `url(` values excepted), type metrics (font-size, weight, line-height, letter-spacing), padding, margin, gap, grid tracks, radius, border, box-shadow, backdrop-filter, display and flex or grid alignment, position and offsets, z-index, cursor, `max-width`, the `width`, `height` and `x-rect-*` of layout boxes (sections, containers, columns, media frames), and the final `transform` and `opacity` of each state. A pseudo-element's `content` string is copy, handled as a slot, never asserted. What depends on the content leaves this layer only through the content probe below, never by judgment.
- `layer: "motion"`: `transition-*`, `animation-*`, `scroll-behavior`.
- `layer: "substituted"`: only `font-family` (when an open substitute is used), and `src` and `background-image` values that contain `url(`. The strict comparator fails any other prop labelled `substituted` and prints the substituted count per viewport, which the README reports. List every substituted value, with the original and clone values, in `WS/substitutions.json`.
- Pseudo-properties (the only non-CSS props allowed): `x-rect-top`, `x-rect-left`, `x-rect-width` and `x-rect-height` in px, and `x-line-count` (number of distinct line boxes from `Range.getClientRects()` over the block's text) and `x-line-starts` (the first word of each line joined by `/`), which are always `content`.
- `layer: "content"`: content-dependent entries, recorded for the original as slot budgets and never compared with it for equality: every `x-line-*` entry, and the entries the content probe moves here. The copy-fit gate (§5) checks them; the strict comparator skips and counts them, and fails any `content` entry that is neither `x-line-*` nor listed as changed in `WS/gates/content-probe.json`.
- **Content probe.** Load the original and, in the browser only (nothing is sent), put the clone's content into its slots: each text slot gets its `site.json` value and each image a same-size neutral data-URL placeholder. Re-read every `rest` entry and every slot's `x-line-count`, and save both to `WS/gates/content-probe.json` with the SHA-256 of the `site.json` it injected, which must equal the shipped one. An entry whose value moves beyond tolerance depends on the content: move it to `content`, logged in `assertion-changes.md` with the probe as its measurement. An entry whose element disappears under the probe stays in `rest`. Re-run the probe whenever `site.json` changes.
- Coverage: your assertion builder prints `archetypes covered: X/Y` and `states covered: X/Y`. Both must be 100%.
- **Lock.** `WS/assertion-changes.md` starts with the initial SHA-256 of `assertions.json`. Every change appends the reason, the measurement file it came from and the new SHA-256, and rewrites `WS/gates/assertions.lock`. Regenerate assertions only from a new measurement of the original (the content probe counts as one). Each change is its own commit in the `WS` repository.

## 4. Rebuild it

Every page in scope, every component, every state, at every breakpoint, in a modern framework of your choice, filled with the client's content. The motion is part of the clone: rebuild the original's own scroll behaviour, page transitions, hover choreography, entrance animations and any WebGL or canvas work first, and only then anything else. For WebGL and canvas, author the effect yourself from what recon recorded. A static skin over a site whose whole identity is motion is a failed clone.

- **Fonts.** If the original's font is commercial, use the client's licensed files when supplied (`CLIENT_INPUT/fonts`, licence in `rights.md`); otherwise choose the closest open font by measuring about 30 candidates against the live font (cap-height-normalised text width, x-height, uppercase width). ## 5. Prove the match

**The comparator.** The contract names `assert-styles.mjs` as the gate, and you run it, but on its own it can pass a false match: it compares only the first number in any value that has units. Reproduced: a `padding` of `10px 60px` passes against an expected `10px 20px`, and a `box-shadow` with a different colour, offset and blur passes when its first number matches. Also reproduced: `opacity` 0 against 1, `transition-duration` 0.3s against 1.2s, `z-index` 10 against 11 and a line count of 3 against 4 all pass. So write `WS/tools/assert-strict.mjs`, which reads the same two JSON files plus each assertion's `layer` and compares token by token.

- Tolerances: `px` ±1, `em` and `rem` ±0.01, `%` ±0.5, `s` ±0.005, `ms` ±5, `deg` ±0.5, opacity and colour alpha ±0.01; in `matrix()` and `matrix3d()` the translation entries ±1 px and every other entry ±0.001. Colour channels, unitless numbers (`font-weight`, `z-index`), keywords and function names must match exactly, and a value with a different number of tokens fails. A selector or property missing from the clone's styles is a failure, never a skip. `substituted` and `content` entries are skipped and counted, subject to the allowlists in §3.
- Exit 0 only when `rest` and `motion` have zero failures.
- Smoke test before you use it, saved to `WS/gates/strict-smoke.txt`, with exactly these six cases: `transform-origin` `10px 20px` against `10px 60px` (must fail); `box-shadow` `rgba(0, 0, 0, 0.5) 0px 4px 12px 0px` against `rgba(0, 255, 255, 1) 0px 40px 90px 30px` (must fail); `opacity` `1` against `0` (must fail); `transition-duration` `0.3s` against `1.2s` (must fail); `width` `400px` against `400.9px` (must pass); a selector missing from the clone's styles (must fail). The upstream script passes the first four.

Run both comparators and save both outputs. The strict one is the gate.

**Clone gate.** Drive each state exactly as a user would (move the pointer, hover, click, scroll in steps, wait for transitions to end), read `getComputedStyle` for every asserted key into `clone-styles.json`, and run the comparators. Iterate the convergence loop until there are zero `rest` and `motion` failures and `npm run build` exits 0.

**Target validation (required).** Assertions are keyed by original selectors, and `WS/selector-map.json` maps each to a clone selector. Run the same reader against the live original, and against the clone through the map, scored with the same assertions. Every mismatch means the spec recorded an authored value where the runtime computes something else (for example a JS-injected `cursor: none`, or an unscoped variable falling back to black). Correct the assertion to the runtime value (log it in `assertion-changes.md`), fix the clone to match, and re-run both. Final state: the clone has 0 failures and the original has 0 failures on the same `rest` and `motion` set (excluding states marked `state-changing on a live site`, and `content` entries). Record the URL, capture date, viewport, font-load state and interaction state with both runs. If the live site changes during your build, refresh the baseline and say so.

**Copy-fit gate.** With the shipped content in place, for every text slot in `WS/slots.json` at every viewport: the clone's `x-line-count` is within ±1 of the content probe's for the same content (a larger gap is a fidelity failure: widths or type are wrong, so fix the clone); the probe's count against the original's own is the copy-fit budget (a deviation beyond ±1 is a copy-fit note with a recommended length in `docs/CONTENT_NOTES.md`, not a failure); no text is clipped by an ancestor whose `overflow` is not `visible`, no two text slots overlap unless they do in the probe, and the page has no horizontal scroll; text over images keeps 4.5:1 contrast (3:1 for large text), computed with the text hidden as the 5th-percentile contrast of the background pixels under its line boxes; every image slot holds a client image or a marked placeholder. Where the client's copy overflows a box the design fixes in size, keep both the design and the copy: the slot is `FAIL`, with a recommended length in `docs/CONTENT_NOTES.md`, for the client to decide. Save `WS/gates/copy-fit.json`.

**Motion gate.** Record every recorded motion sequence on both sites with the same in-page `requestAnimationFrame` recorder, started by the same dispatched trigger event. End values must be within the rest tolerances. Completion time, the first frame after which the value stays within tolerance of its end value, must be within ±50 ms. At each 16 ms step, `abs(clone - original) / max(abs(range), 1 unit)` must be at most 0.08, where range is end minus start of the original; a property with zero range is compared with the rest tolerances. For scroll-driven motion, progress-based effects are compared at the same section progress (§2) and per-pixel factors at the same scroll distance from the section's start, and must meet the rest tolerances. Anything you cannot measure numerically (shader output, for example) goes in a list of unmeasured items with a frame-strip comparison instead.

**Production gate.** Write `WS/tools/prod-audit.mjs`. It runs every checklist row whose Verify column names a command or snippet, against `npm run start` with `SITE_ENV=production` unless the row says otherwise, at the four viewports (and in Chromium, WebKit and Firefox where a row says so), and writes `WS/gates/production.json` (row ID, status, measured value, evidence path) plus a readable `WS/gates/production.md`. Smoke test before use, saved to `WS/gates/prod-smoke.txt`: on a deliberately broken fixture (a server that answers 200 for a missing path, a page with no `lang`, an image without `width` and `height`) it must fail SEO-03, TYP-05 and SPD-04. Record each `FIDELITY-EXCEPTION` in `WS/fidelity-exceptions.md` (row, the original's value, the cost of fixing it, what you did instead).

**Convergence loop** (contract §6). At most 10 cycles. Two consecutive cycles with no drop in failures, from cycle 2, end the loop as `STUCK`; reaching the cap is `CEILING`. Either one ends the loop, not the run: write `WS/escalation.md` with the remaining failures, record gate 1 as `FAIL`, and carry on with every later step; the polish pass is then `NOT_RUN`, because its baseline needs green gates. A build that will not compile is a defect to fix, never a reason to stop; if the loop ends with it broken, ship the last commit that builds and report the failure. Never present a failure as passing.
